# Sistema i18n - Documentación

## Arquitectura del Sistema de Internacionalización

El sistema i18n sigue una arquitectura modular y personalizada sin dependencias externas:

```text
src/
├── core/
│   ├── i18n/
│   │   ├── index.js       # Punto de entrada principal
│   │   └── i18n.js        # Lógica del sistema i18n
│   └── utils/
│       └── dom.js         # Utilidades DOM para i18n
└── locales/
    ├── es.js              # Diccionario español
    └── en.js              # Diccionario inglés
```

---

## i18n/index.js

**Propósito**: Punto de entrada unificado para el sistema i18n.

### Características

- Exporta todas las funciones del módulo principal
- Permite importaciones limpias: `import { t, setLanguage } from './core/i18n'`
- Patrón barrel para simplificar la API pública

## i18n/i18n.js

**Propósito**: Sistema completo de internacionalización personalizado.

### Configuración Inicial

#### Constantes del Sistema

```javascript
const DICTIONARIES = { es, en }; // Diccionarios disponibles
const STORAGE_KEY = "jojo_os_language"; // Clave para persistencia
const DEFAULT_LANGUAGE = "en"; // Idioma por defecto
```

#### Estado Interno

```javascript
let currentLanguage = DEFAULT_LANGUAGE; // Idioma actual
const listeners = []; // Callbacks para cambios
```

### Detección Automática de Idioma

La función `detectLanguage()` sigue un orden de prioridad:

1. **LocalStorage** - Revisa si hay un idioma guardado previamente
2. **Navegador** - Detecta el idioma del navegador (`navigator.language`)
3. **Default** - Usa inglés como fallback

**Ejemplo de detección:**

- `es-MX` → `es` (soportado)
- `en-US` → `en` (soportado)
- `fr-FR` → `en` (no soportado, usa default)

### API Pública

#### `t(key)` - Traducción

**Propósito**: Traduce claves usando notación de puntos

**Parámetros:**

- `key`: String en formato `'section.item'`

**Ejemplos:**

```javascript
t("system.boot"); // "INICIANDO SISTEMA..."
t("ui.projects"); // "Proyectos"
t("bio.intro"); // "Soy Joel, un desarrollador..."
```

**Características:**

- Navegación segura por objetos anidados
- Retorna la clave si no encuentra traducción
- Soporta estructuras profundas

#### `setLanguage(langCode)` - Cambiar Idioma

**Propósito**: Cambia el idioma actual y notifica a los componentes

**Parámetros:**

- `langCode`: Código de idioma (`'es'`, `'en'`)

**Retorno:** `boolean` - `true` si tuvo éxito, `false` si no existe

**Comportamiento:**

1. Valida que el idioma exista
2. Actualiza el estado interno
3. Guarda en localStorage (persistencia)
4. Notifica a todos los listeners
5. Log de debugging

#### `getLanguage()` - Obtener Idioma Actual

**Propósito**: Retorna el código del idioma activo

**Retorno:** `string` - Código de idioma actual

#### `onLanguageChange(callback)` - Suscripción a Cambios

**Propósito**: Permite a componentes reaccionar a cambios de idioma

**Parámetros:**

- `callback`: Función que recibe el nuevo idioma

**Retorno:** `function` - Función `unsubscribe` para limpiar el listener

**Uso típico:**

```javascript
const unsubscribe = onLanguageChange((newLang) => {
  updateUI(newLang);
});

// Para limpiar el listener cuando sea necesario
unsubscribe();
```

## Flujo de Trabajo y Patrones

### 1. Inicialización

```javascript
// El sistema se auto-inicializa al importar
import { t } from "./core/i18n/i18n.js";
```

### 2. Uso en Componentes

```javascript
// Traducción simple
const bootMessage = t("system.boot");

// Suscripción a cambios con cleanup
const unsubscribe = onLanguageChange((lang) => {
  console.log(`Idioma cambiado a: ${lang}`);
});
```

### 3. Cambio de Idioma

```javascript
// Cambio manual
setLanguage("es"); // true si éxito, false si error

// El sistema persiste automáticamente
```

## Características Avanzadas

### Persistencia Automática

- Usa `localStorage` para recordar preferencias
- La clave `jojo_os_language` es única para la aplicación

### Sistema de Eventos con Cleanup

- Pattern observer para notificar cambios
- Los componentes se suscriben sin acoplamiento directo
- Función `unsubscribe` para prevenir memory leaks

### Manejo de Errores

- Retorna la clave si no encuentra traducción
- Validación de idiomas soportados
- Logging para debugging

### Performance

- Carga lazy de diccionarios
- Cache del idioma actual
- Mínimas dependencias

## Extensión y Mantenimiento

### Agregar Nuevo Idioma

1. Crear `locales/xx.js`
2. Exportar el diccionario
3. Importar en `i18n.js`
4. Agregar a `DICTIONARIES`

### Agregar Nuevas Traducciones

1. Agregar clave a todos los diccionarios
2. Usar notación de puntos para estructuras profundas
3. Mantener consistencia en nomenclatura

### Buenas Prácticas

- Usar claves descriptivas (`system.boot` vs `msg1`)
- Mantener estructura consistente entre idiomas
- Probar con claves inexistentes
- Validar persistencia en navegador
- Limpiar listeners con `unsubscribe()`

## Inicialización en main.js

### Flujo de Inicialización

El archivo `main.js` establece la conexión entre el sistema i18n y el DOM:

```javascript
import { onLanguageChange } from "./core/i18n/i18n.js";
import { updateLocalizedText } from "./core/utils/dom.js";
```

### 1. Suscripción a Cambios de Idioma

```javascript
onLanguageChange(() => {
  updateLocalizedText(); // Repinta textos cuando cambia el idioma
});
```

**Propósito**: Establece el binding reactivo entre i18n y la UI

**Comportamiento:**

- Cada vez que `setLanguage()` se ejecuta, se llama a `updateLocalizedText()`
- Actualiza todos los elementos con atributos de traducción
- Mantiene la UI sincronizada con el idioma actual

### 2. Inicialización del DOM

```javascript
document.addEventListener("DOMContentLoaded", () => {
  updateLocalizedText(); // Carga inicial con idioma detectado

  // Inyección del componente de idioma
  const app = document.getElementById("app");
  const switcher = document.createElement("x-lang-switch");
  app.appendChild(switcher);
});
```

**Secuencia de inicialización:**

1. **DOMContentLoaded**: Espera que el HTML esté cargado
2. **updateLocalizedText()**: Aplica traducciones iniciales (usando idioma detectado)
3. **Component Injection**: Crea e inyecta el switcher de idioma

### Patrón de Integración

#### Binding Reactivo

- **i18n** → **DOM**: Los cambios de idioma actualizan automáticamente la UI
- **Componentes** → **i18n**: El switcher puede cambiar el idioma global

#### Separación de Responsabilidades

- **main.js**: Orquesta la inicialización y binding
- **i18n**: Gestiona el estado de idioma
- **utils/dom.js**: Maneja la actualización del DOM con `updateLocalizedText()`
- **LanguageSwitcher**: Provee la UI para cambiar idioma

El sistema i18n está diseñado para complementar el tema cyberpunk/terminal:

- **Mensajes de sistema**: Estilo terminal retro
